# Session Notes 2026-03-15: TradeUI Deep Reimpl Fixes

## Summary
Fixed multiple crash-causing bugs in TradeUI reimplementation. 6 of 8 vtable methods
now fully reimplemented (Draw, Slot6, OnCreate, OnRemove, Update, ScalarDtor).
Serialize and Startup remain trampolined pending further work.

## Bugs Found & Fixed

### 1. Dispatch Slot Type ID Double-Deref (engine_funcs.cpp)
**Slots 0x140151510 (TableElement) and 0x1401516c8 (SpinnerElement)** contained
pointers TO type IDs, not type IDs directly. The original asm does:
```
MOV RAX, [slot]   ; read pointer from slot
MOV EDX, [RAX]    ; read type ID from pointer
```
But the code did single deref — reading low 32 bits of a pointer as type ID.
Fixed by adding the `resolveTypeId` / exref double-deref pattern.

**Gotcha**: Pre-cached `g_TypeId_*` pointers from these dispatch slots gave garbage
values (e.g., 0x5310BDA4) at runtime. The exact mechanism is unclear — possibly the
slots contain External references that need deeper understanding. For the Serialize
inner loops, we ended up removing IsDerivedFrom type checks entirely since the dialog
template guarantees child element types.

### 2. Wrong Component Lookup: StateMachine vs Storage
**Entity_FindComponent_StateMachine (0x140006270)** was mislabeled in Ghidra. It
actually uses type ID DAT_1401c7e78 = StorageComponent. Renamed to
`Entity_FindComponent_Storage`. Affected 5 functions in tradeui.cpp:
- TradeUI_Startup
- TradeUI_RefreshSellTable (was `fn_FindComponent_SM`, different abbreviation)
- TradeUI_RefreshOrderQuantityDisplay
- TradeUI_RefreshSellSpinnerValues
- TradeUI_RefreshDisplay (was already correct)

### 3. System::String vs UI::String Mismatch
`TextElement::SetText` expects a 16-byte `UI::String` (with StringTable pointer),
not an 8-byte `System::String`. Using `fn_String_Ctor_Copy` or `fn_String_Ctor_Default`
creates the wrong type, causing null StringTable → crash in `StringTable::GetText`.
Fixed 6 call sites to use `fn_UIString_Ctor` / `fn_UIString_DefaultCtor`.

### 4. tablePurchase Flat Indexing (Stride 3)
tablePurchase uses **flat indexing** where each logical row = 3 consecutive children:
- child[k] = compound cell with sub-child(0)=label, sub-child(1)=number
- child[k+1] = button (standalone)
- child[k+2] = spinner (standalone)
Loop bound is `+0xC0` = row count, not total child count.

Other table loops (tableStorage, tableSell, tableBuy) use FindElement("ribbonXxxRow")
for true two-level access — those were correct.

### 5. CloneTableCells Ordering
Template must be read from first child's `+0xB8` BEFORE `SetSize` destroys children.
The reimpl called SetSize first, then tried to read the template → null crash.

### 6. New Function Pointers Added
- `fn_UIString_DefaultCtor` — dispatch slot 0x140151ca8
- `g_TypeId_SliderElement` — exref 0x140151cf0

## Architecture Lessons Learned

### Dispatch Slot Types (0x14015xxxx)
These dispatch table slots have DIFFERENT internal structures:
- Some contain pointers to type IDs (double deref needed)
- Some contain function pointers
- Some contain External references (complex deref chain)
- Pre-caching at DLL init time can give stale/wrong values
- Safest approach: read fresh from slot at runtime (ReadDispatchTypeId helper)
- For inner loops, if type checks are just validation, consider skipping them

### UI::String vs System::String
- `System::String` = 8-byte COW refcounted string
- `UI::String` = 16-byte struct with StringTable pointer + string name
- `TextElement::SetText` expects UI::String
- `fn_UIString_Ctor(retbuf, stringTable, stringName)` creates UI::String
- `fn_UIString_DefaultCtor(retbuf)` creates empty UI::String
- `fn_String_Ctor_*` functions create System::String — WRONG for SetText

### Table Element Flat Indexing
CLAUDE.md already warned about this:
> TableElement children are accessed via flat index (colCount * row + col)
The tablePurchase loop is a concrete example with stride 3 (compound cell + 2 standalone elements per row).
