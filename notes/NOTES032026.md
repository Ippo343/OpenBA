# Session Notes 2026-03-20: Entity_helper_9ed0 Crash Investigation

## The Crash
- **Address**: `0x140089FCA` in `Entity_helper_9ed0` (resource tally function, 0x140089ed0-0x14008a723)
- **Fault**: ACCESS_VIOLATION reading `0xFFFFFFFFFFFFFFFF`
- **RCX**: `0xCCCCCCCCCC0000C2` — this is `PlayAnimation_Draw` at `0x1400C4B90` (`RET 0x0` = `C2 00 00` + INT3 padding `CC CC CC CC CC`) read as a little-endian qword
- **RBX**: `0x1400DFF80` — inside `TutorialHighlightDialog_helper_fda0` (code, not data)
- **What happens**: `Entity_helper_9ed0` iterates entity IBP arrays in a CitizenBehavior struct, finds exe .text addresses instead of heap entity pointers, reads code bytes as vtable → crash

## Root Cause: IBP Double-Dereference Bug Class
When `fn_Entity_FindComponent*()` stores a result into a **scalar** `uintptr_t` local:
```cpp
uintptr_t compIBP = 0;
fn_FindComponent(entity, &compIBP);   // stores component ptr into compIBP
fn_InternalBasePtr_CheckPtr(&compIBP); // no-op (already resolved)
// compIBP now IS the component pointer
```

**The bug**: `*(uintptr_t*)compIBP` treats the component pointer VALUE as an ADDRESS, reading the vtable (an exe .rdata address) instead of using the component pointer directly. This propagates exe addresses into entity data structures.

**NOT a bug** for array-based IBPs: `uintptr_t meshIBP[2] = {0}; *(uintptr_t*)meshIBP` reads `meshIBP[0]` which is correct.

### 5. GatherRawMaterials — 4 critical fixes (DONE, Session 2)
Bisected to GatherRawMaterials as second crash source (after BuildStructure).

**Bug A: PathfindingFindPath wrong pointer level (CRITICAL — root cause of entity IBP corruption)**
- File: `code/Game/Work/gatherrawmaterials.cpp` line ~632
- Reimpl passed `worldEntityList` directly as 1st arg
- Original uses a 3-qword **stack buffer** `local_58[3]` with `[0]=worldEntityList`
- PathfindingFindPath writes output into this buffer — passing the raw pointer overwrote the global world entity list, corrupting IBP arrays
- Fix: `uintptr_t pathBuf[3] = { (uintptr_t)worldEntityList, 0, 0 };` passed as 1st arg

**Bug B: FindStorageForResource wrong 8th parameter**
- Reimpl passed `&self->field_10` (work entity IBP address)
- Original passes address of a local null-initialized IBP `&local_b8`
- Fix: `uintptr_t excludeIBP = 0; ... &excludeIBP`

**Bug C: Storage slot search — used wrong index on match**
- Original loop: starts from slot 0, uses CURRENT index `R8D` when match found
- Reimpl had `foundSlotIdx` tracking PREVIOUS index → read wrong slot data → `availableAmount=0` → `remaining=0` → citizens stuck
- Verified against assembly at `0x1400ec214`: `CMP [RCX],RAX / JZ match / INC R8D / ADD RCX,0x10`
- Match handler at `0x1400ec371`: `TEST R8D,R8D / JS skip / MOVSXD RAX,R8D / MOV ECX,[R10+RAX*8+8]`
- Fix: simple `for (si=0; si<count; si++)` with `si` used in match handler

**Bug D: s_fn_MemFree resolved from wrong IAT slot**
- `0x1401527f0` IAT slot contains `0x18001D450` (Runtime DLL data address, NOT MemFreeStatic)
- Calling it as a function → ACCESS_VIOLATION WRITE to `0x18001D450`
- Fix: replaced all `s_fn_MemFree()` calls with `fn_MemFreeStatic()` from engine_funcs.h
- **General rule**: Never resolve MemFree from exe IAT/dispatch slots — always use `fn_MemFreeStatic`
