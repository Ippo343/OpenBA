# INVENTORY B2 — raw vtable-slot reads in `code/Game/` (NEXT_SESSION §3b question 1)

Read-only inventory, written 2026-09-28 against `main` (deaf604c + working tree). Scope: `code/Game/` only
(runtime / standalone / dx11 / tests belong to the other inventory agents). Nothing was built or run.

**What was measured.** Every place in `code/Game/` that calls (or reads, or null-tests) a virtual function by
SLOT INDEX instead of by name: `vt[N]`, `*(fn*)(vptr + 0xNN)`, `(*(R(**)(…))(*(uintptr_t*)p + 0xNN))(p)`,
`*(fn*)vptr` (slot 0 with no index), `(*(void***)p)[N]`, and slot-index helpers (the `slotOf` lambda). Under the
normal-virtual cutover a class whose slot 0 is `DeletingDtor(unsigned)` gets `virtual ~T()` = TWO slots, so every
such read on a flipping class calls its neighbour. Each row below names the class, the slot, the header member and
the by-name replacement.

**Method.** `partc.py --list` for the four slot patterns (code/ lines kept), then scratch scanners
(statement-level, comments stripped with `codegrep.strip`, strings blanked) over `code/`: (a) `R(**)(args)`
function-pointer-pointer casts; (b) every locally `typedef`'d function-pointer type used as `*(Fn*)(expr)` /
`(Fn)expr[...]`; (c) index-then-call `X[i])(`; (d) variables loaded from an offset-0 deref (`v = *(T**)obj`) then
indexed or offset; (e) C-cast `(*(void***)p)[N]` reads with no call. IAT / dispatch-slot reads
(`*(Fn*)ResolveAddr(...)`, 89 statements, none a vtable) were separated out and field-offset data reads discarded.
Every surviving site was read in context; the class was derived from where the pointer came from, the slot name
from the class header. Anything not derivable is marked **NOT VERIFIED**.

**Legend.** *flip?* — `FLIP`: the class's slot 0 is `DeletingDtor` (it turns virtual and every later slot shifts);
`EXEMPT`: slot 0 is not a destructor, the table must NOT shift. *KIND* — `MEMBER` (replace with a by-name virtual
call), `DELETE` (slot 0 with flag 1 → `delete p`), `DESTRUCT` (slot 0 flag 0; **none found** in code/Game),
`EXEMPT-TABLE`, `DIAGNOSTIC` (reads / null-tests / prints a slot, or a debug probe), `NOT-A-VTABLE`,
`TABLE-BUILDER` (**none found** in code/Game). *partc* — whether `partc.py --list` reports the site (±2 lines).

## Obstacles (read before converting)

1. **Receiver is `void*` / `uintptr_t` / `int64_t*` almost everywhere.** No site has a typed receiver except
   `tradework.cpp:313` (`TradeWork*`). The replacement is a `reinterpret_cast<Class*>` at the call — the bridge
   shape already used at `citizenai_growup.cpp:223` and `buildrequirementui.cpp:83`
   (`reinterpret_cast<Object::Base*>(obj)->Type()`). Every class named below derives from its root at offset 0
   (single inheritance), so the cast is layout-safe.
2. **Argument-list mismatches between the call site and the header** (header lists are marked NOT VERIFIED in the
   Action.h:28-31 and Component.h:30-34 banners, "B38_RULES §6 NOT VERIFIED"). A by-name call will not compile until one side is corrected from
   retail: `Work::Validate` called with `this` only (action_base_complete.cpp:316, citizenai_housing_idle.cpp:509,
   goals_serialize.cpp:377/833, work_base_grid.cpp:77/90); `Work::Execute` called with 2 args, header has 3

   (charactercomponent.cpp:79); `Action::AbstractImpl` called with none (citizenai_executor.cpp:134);
   `Component::OnEvent(int)` called with none (buildcomponent.cpp:258); `UI::Element::Enable(bool)` called with none

   with `this` DROPPED (citizenaicomponent.cpp:181, fishingwork.cpp:649 — harmless today because Type() never reads
   RCX). Each must be read against retail before its conversion (memory: Ghidra drops args on indirect calls).

inventory's scope) — listed here for completeness.
