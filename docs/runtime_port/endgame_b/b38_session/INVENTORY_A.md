## 1. Per-class table

Column notes: "per-slot" for the 48-slot component tables is computed as FillTypedVtable's
defaults (0 = `Inert_ScalarDtor` → "stub", 2 = per-type GetTypeId → "own", 3 =
`Component_SerializeReimpl_Fwd` → "base", rest inert) overlaid with the factory macro's fixed slots
and every `X_LiveVtable[N] = …` store in the file. For initializer tables it is a name classifier:
functions named after the class = own, shared `Work_*` / `Action_*` / `ResourceProduceComponent_*`
/ `ControllerLive_*` = base, `*Return0/Return1/ReturnNull/VtblStub/PureCall/Nop*` = stub. In the
description tables "stub" is often the faithful body (GetVersion is a constant, slot 4 `Compile`
is the shared `0x14003a912`), so read it as "shared trivial helper", not "wrong". "retail vtable" =
the RegisterExeAddr target if the table is registered, else the POD header's `Vtable` constant
marked "not registered". POD sizes are the header's `static_assert(sizeof)`; alloc is the size the
tree's factory allocates.

### 2.4 What a compiler vtable does differently (per mechanism)

1. **Size.** Components: 48 vs retail 16/18/22 (every table). Descriptions 11 vs 10. Work 13 vs 13
   (AutoPickupWork base 13 vs banner 12). Action 10 vs 10. ComponentEntity 12 vs 4. Model 24 vs 16
   (banner claims 19). Dispatcher 16 vs 9. A compiler table has exactly the declared virtuals;
   nothing in the tree may index past retail's count. Four tables ALREADY do (surprise 2).
2. **Inert slots inside retail's range** — 726 component slots (of 1,152 in-range): a compiler
   vtable puts the `Component`/`ControllerComponent` base body there. Retail's Component base
   bodies for slots 4-15 are `0x140118a50 … 0x140118ae0` and `0x140118820/830`, spaced 0x10 apart
   (≤ 16-byte bodies — `ret` / `xor eax,eax; ret` class), so the inert stub is behaviourally the
   base for those EXCEPT where the return width/value matters (not measured per slot — 0C's
   dump decides). Slot 1 (`GetTypeInfo`) is the exception: retail returns the per-class type-info
   global; the tree returns 0 in 49 components (only the 17 `CONTROLLER_LIVE_FACTORY_STATES` /
   hand-rolled Boat/Forester/Trade/Pasture fill it) and in all 82 descriptions (`VtblReturnNull`).
   Slots 16/17 are PURE in `ControllerComponent` (`0x14003addc` at 0x140162c00/08, READ); the tree
   leaves them inert in AbsorbResource, MarketLocation, MultiObject.
3. **Slot 0.** 66 components use one shared `Inert_ScalarDtor` that runs only `~Internal`: no
   `~Component` (retail 0x140031cc0), no `~ControllerComponent` (0x140032800), no member dtor. A
   compiler dtor chains all of them. 6 descriptions skip `~External` (table, slot-0 column).
   All 17 actions share `Action_ScalarDtor`.
4. **Tables filled at init from a live object** — `s_siGeomVtable` and
