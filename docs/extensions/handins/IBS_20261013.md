## 2. What this pass settles

- The four blocks did what their shadows and A/Bs said: GetBones and StateMachine::Tick left the table, the cull
  halved per box, the sort trades compares for words.
- The faithful draw path at uncapped fps is now ~70% of the main thread's ops in four blocks: gather (misses), cull
  (ALU), sort (ALU), per-item transforms (misses + ALU). The sim is a rounding error at speed 10; the speed-50 split
  (the PERFDAY_20261012 section 5 collect) is still the one to take before any more sim work.

## 3. Ideas for the next session (new, in order of expected ms per unit of risk)

1. **Per-draw-item transform memo (faithful, exact, the SKINMEMO argument).** `GetInstanceTransform` +
   `RtLerpTransformPair` + the `AsMatrix` / `Lerp` they call + `SetTransform`'s compare are ~20% of main-thread ops
   with 17-47% miss rates. Within one `Renderer::Draw` the same geometry is drawn in several passes and lists with the
   same `t` (SKINMEMO's row: 2.7-2.9 requests per key), so the lerped world matrix per (geometry, node, t bits) can be
   computed once per Draw and copied. Same scope guard as SkinMemo, same census (`_transform` pair and `_nodes`
   writers inside a Draw), shadow `ItemTransform`, row `/xform`. Ceiling: most of the ~20% minus one computation per
   key; realistic -5..-10% of draw CPU.
2. **Route the remaining reference frustum callers to the fast body (faithful, exact).** `SelectVertices` 2.6% +
   `RtVolume_Frustum_Contains` 2.3% still run: find the callers FRUSTUMCULL did not touch (the sun / spot shadow
   groups' own cull, picking, the minimap?) and give them the prepared planes. A 2-hour block with the existing
   shadow; -3..-5% of main-thread ops.
3. **The sort: fewer compares, not cheaper ones (faithful, exactness to prove).** 13.6 compares per item on 2,700
   items per sort x 9 sorts per frame; `KeyLess` is 7% of ops. The exact options: (a) an LSD / counting pass on the
   first key word (`_flags` 16 bits, the float key) before the introsort, which keeps the swap sequence only if the
   skeleton's decisions never see an inversion across buckets -- that is a proof, not a hope; (b) the plain
   `std::sort` / radix over the whole key, exact iff ties never occur (the DRAWSORT row read 0 ties and 0 arg8-differing
   ties in this town; a census in a town with instanced batches is the gate); (c) skip the sort for a pass whose list
   has not changed order since the last frame (same items in the same order, keyed by a hash of the key array): the
   scene changes every frame at speed 10, so measure the hit rate first. Ceiling 15% of ops; realistic (b) -8..-10%
   once the census allows it.
4. **A prefetch-ahead in the faithful gather (faithful, hints only).** `AddCulledDrawItems` at 40.6% L1 miss / 4.3%
   latency: in the cell chain walk, prefetch the Geometry's two lines (+0x28 and +0x4c) one or two objects ahead, the
   way the walk's staged pipeline does. The class A `draw_gather` side array already removes the misses when ON; this
   would take ~half of them in the faithful profile with no extension and no census. Ceiling ~4% of ops.
5. **The speed-50, everything-on IBS collect** (PERFDAY_20261012 section 5, still open): the sim-heavy split with
   `walk_batch`, `fast_paths`, `path_workers`, `draw_gather`, `render_culling` on, now with the overlay rule applied.
   One collect, the user's hypervisor still off.
6. **Housekeeping to decide:** restore the hypervisor (`bcdedit /store ... hypervisorlaunchtype auto`, WSL2 / Docker
   are down until then); `ibs_thread.py`'s block offset should find the thread block by name instead of a line number;
   the stress harness could log `tasklist` for `rtss` beside `machine load` so a capped run announces itself.

Not ideas: DOD / struct layout in the sim (the sim is <5% of the main thread at speed 10 and its misslat is 0.1%);
anything in the pathfinding worker beyond `fast_paths` (class B, already shipped).
