### Key Architectural Discoveries

**5 ControllerComponent vtable offset patterns:**
- Standard: +0x28 (most components)
- HappinessComponent: +0x30
- AttendanceComponent: +0x38
- PastureComponent: +0x48
- NomadComponent: +0x58
- TradeComponent: +0x88 (most unusual — 0x60 bytes of trade data between Component base and controller vtable)

**3 large embedded sub-objects found in rendering components:**
- `Graphics::MeshInstance` — 0x120 bytes (in ModelComponent, CitizenComponent)
- `Graphics::EdgeMeshInstance` — 0xD0 bytes (in HighlightComponent)
- `Graphics::Geometry` — 0xC0 bytes (in StatusIconComponent)

**Component inheritance patterns:**
- 3 inheritance levels: Component -> ControllerComponent -> ResourceProduceComponent
- 5 components are minimal wrappers with no extra fields beyond their base (StorageLocation, MarketLocation, AbsorbResource = ControllerComponent; Market = ResourceProduceComponent; Healer = ControllerComponent)
- 3 minimal components at exactly 0x28 bytes (Mine, Quarry, Zone)
- Largest: CitizenComponent at 0x290 bytes (embedded MeshInstance)

**UI base class layouts:**
- DialogInstance base: 0xB8 bytes, inherits Object::Internal (vtable + index + randomId)
- DialogController base: 0x30 bytes, same Object::Internal inheritance
- UI::Element base: 0xC0 bytes
- UI::Sprite: 0x10 bytes (SpriteSheet* + spriteIndex)
- TutorialGoalDialog and TutorialSetupDialog extend Object::External, NOT DialogInstance

**State Machine Action hierarchy:**
- Object::Internal -> Action (0x20) -> direct actions (MoveTo, PerformWork, etc.)
- Action -> Work (0x48) -> work types (FireWork, FishingWork, etc.)
- Work -> AutoPickupWork (0x48) -> auto-pickup types (ForesterWork, HarvestArea, etc.)
- MoveTo is the largest action at 0x480 (1152 bytes) — contains full pathfinding state

**Performance hotspot confirmed:**
- StorageComponent_QueryCount (0x14012cf10, 44 xrefs) iterates storage slots, per-slot iterates items with IsDerivedFrom type check — O(n*m) per citizen per tick
